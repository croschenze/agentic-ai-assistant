🔥 Firebase Realtime Database 设置指南

解决本地互通问题的完整配置步骤

📋 问题诊断

如果巫师和被测者信息在本地不互通，最可能的原因是 Firebase 安全规则 阻止了数据的读写访问。

Firebase 默认的安全规则会拒绝所有未经授权的访问，这是为了保护数据安全。

步骤 1: 访问 Firebase 控制台

  1. 打开浏览器，访问 https://console.firebase.google.com
  2. 使用您的 Google 账户登录
  3. 选择您的 Firebase 项目
📸 这里应该显示 Firebase 控制台主页面的截图

步骤 2: 进入 Realtime Database 设置

  1. 在左侧菜单中找到并点击 "Realtime Database"
  2. 如果还没有创建数据库，点击 "创建数据库"
  3. 选择数据库位置（建议选择离您最近的区域）
  4. 在安全规则选择中，选择 "以测试模式启动" 或稍后手动配置
📸 这里应该显示 Realtime Database 页面的截图

步骤 3: 配置安全规则

  1. 在 Realtime Database 页面中，点击 "规则" 标签页
  2. 您会看到当前的安全规则配置
  3. 将规则替换为以下内容（仅用于开发测试）：
⚠️ 重要警告： 以下规则仅适用于开发和测试环境！在生产环境中使用会导致数据完全暴露！
{ "rules": { ".read": true, ".write": true } }

这个规则允许任何人读写您的数据库。

步骤 4: 发布规则

  1. 输入或粘贴上述规则后，点击 "发布" 按钮
  2. 确认发布操作
  3. 等待规则生效（通常需要几秒钟）
✅ 成功： 规则发布后，您的应用应该能够正常读写数据了。

步骤 5: 测试连接

  1. 返回您的应用程序
  2. 打开 Firebase 规则测试页面
  3. 依次点击测试按钮：
    • 测试连接
    • 测试读取权限
    • 测试写入权限
  4. 所有测试都应该显示成功

步骤 6: 验证实际功能

  1. 打开 巫师页面
  2. 在另一个浏览器标签页或设备上打开 参与者页面
  3. 测试消息发送和接收功能
  4. 确认两端能够实时通信

🔒 生产环境安全规则

当您准备部署到生产环境时，请使用更安全的规则。以下是一些推荐的安全规则模板：

1. 仅允许已认证用户访问：

{ "rules": { ".read": "auth != null", ".write": "auth != null" } }

2. 用户只能访问自己的数据：

{ "rules": { "users": { "$uid": { ".read": "$uid === auth.uid", ".write": "$uid === auth.uid" } } } }

🔧 故障排除

  • 规则发布后仍然无法访问： 等待 1-2 分钟让规则完全生效
  • 连接测试失败： 检查网络连接和 Firebase 配置
  • 读写测试失败： 确认规则已正确发布
  • 实时通信不工作： 检查浏览器控制台是否有错误信息

🎉 完成！

按照以上步骤操作后，您的 Firebase Realtime Database 应该能够正常工作，巫师和参与者之间应该能够实现实时通信。

如果仍有问题，请检查浏览器控制台的错误信息，或联系技术支持。
